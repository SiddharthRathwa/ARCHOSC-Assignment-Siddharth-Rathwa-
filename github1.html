Introduction to Github

Creating a local and remote repository, staging, commiting, pushing to github and
deploying to live website on github page

Section 1

Creating the lab folder

To start the lab I navigated to my local user profile on the machine through This PC → Windows (C:) → Users → my username → Workspace. The Workspace is a secure local storage area that only I can access. Inside it I created a new folder called "ArchOSC Assignment" by right clicking and selecting New then Folder.

Section 1 — Continued

My Local Workspace Folder

This is my personal workspace folder created on my own laptop. Inside it I created the ArchOSC Assignment folder which is where all my project files are stored locally. The workspace is only accessible on my machine and is not linked to OneDrive, which means Git and GitHub communicate much better from this local storage location.

Section 1 — Continued

Initialising Git

I right clicked inside my ArchOSC Assignment folder and selected "Open in Terminal" to open PowerShell. I then typed the command git init and pressed Enter. This sets up a new Git repository in that folder which means Git can now start tracking any files I create or change inside it. The terminal confirmed the repository was created successfully

Section 2

Creating a github repositiory

I went to www.github.com and logged into my account. I clicked the green "New" button to create a new repository. I gave it the name ARCHOSC-Assignment, set it to Private, ticked the "Add a README file" option and set the .gitignore to Visual Studio. I then clicked "Create Repository" which created an online repository on GitHub that I would link my local work to

Section 3

Pushing to Github

In the terminal I typed git remote add origin followed by the link to my GitHub repository. This tells Git where the online repository is so the two can be connected. I then ran git pull origin main to download the files GitHub had already generated such as the README file. A sign in prompt appeared and I authorised access through my browser

Section 3 - continued

Creating a website

I opened Visual Studio Code and created a new file. I pasted in the provided HTML code which creates a simple webpage showing a name in the centre of the screen. I replaced the placeholder text with my own name then saved the file as index.html inside my ArchOSC Assignment folder. I double clicked the file to open it in a browser and the webpage displayed correctly

Section 3 - continued

Staging and committing

I went back to the terminal and typed git status to see what files Git had detected. The index. html file showed up in red meaning Git could see it but was not tracking it yet. I ran git add . to add all files to the staging area. Running git status again showed the files in green confirming they were staged. I then ran git commit -m "Initial commit" to save a snapshot of my work.

Section 4

Deploying with github pages

I went to my GitHub repository and clicked Settings then selected Pages from the left menu. I changed my repository visibility to Public then set the deployment source to my main branch and clicked Save. After a short wait GitHub generated a live link to my website. I clicked the link and my website opened in the browser meaning it was now live and accessible from anywhere with an internet connection.

Reflection

What I Learned

In this lab I learned how to use Git and GitHub to manage and store code. I created a local repository using the terminal, linked it to an online GitHub repository and pushed my files up to be stored remotely. I also built a basic HTML website and deployed it live using GitHub Pages. In industry version control using Git is a fundamental skill used by almost every software development team in the world. It allows developers to track every change made to a codebase, collaborate with others without overwriting each other's work and roll back to previous versions if something goes wrong.
